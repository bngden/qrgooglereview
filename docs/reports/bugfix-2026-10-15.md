## BUG-001 — Fallback rahasia hardcoded pada token reset guest

- **Severity:** P0
- **File:** `lib/services/guest.service.ts:44` (sebelum perbaikan)
- **Reporter Agent:** Agent Perbaikan Bug

### 1. Expected Behavior
Token reset guest ditandatangani dengan rahasia yang hanya ada di env. Bila `JWT_SECRET` tidak diset, permintaan gagal tertutup (error), bukan memakai nilai bawaan.

### 2. Actual Behavior
```ts
const s = process.env.JWT_SECRET ?? 'dev-secret-change-me'
```
Nilai bawaan diketahui publik dari source code. Kunci turunan `${secret}:guest-reset` bisa dihitung siapa pun.

### 3. Reproduction Steps
1. Pastikan `JWT_SECRET` tidak tersedia di environment proses.
2. Hitung HS256 key dari `'dev-secret-change-me' + ':guest-reset'`.
3. Tandatangani token berisi `qr_id` target + `scope=reset` yang berlaku 5 menit.
4. Kirim `POST /api/guest/update` dengan token tersebut tanpa mengetahui kode reset.

### 4. Evidence
- Bukti langsung: guard `requireJwtSecret()` menolak nilai `dev-secret-change-me` (19 karakter < 32).
- Test regresi: `tests/unit/security/secret-guards.test.ts` → `BUG-001: requireJwtSecret`.
- **Tidak ada nilai secret yang dicatat di laporan ini.**

### 5. Impact
- Affected user: pemilik QR mana pun (reset oleh tamu).
- Functional impact: perubahan tujuan QR tanpa membuktikan kepemilikan.
- Security impact: **open redirect** pada kode QR yang sudah tercetak & tersebar → phishing.
- Data integrity impact: `destination_url` berubah tanpa jejak yang sah.

### 6. Suspected Root Cause
Penyalinan pola guard yang tidak konsisten: `jwt.ts` dan `auth.service.ts` sudah strict, `guest.service.ts` memakai fallback. Diverifikasi, bukan hipotesis.

### 7. Reproduction Reliability
Always reproducible (hanya bila `JWT_SECRET` kosong/pendek).

### 8. Suggested Investigation
Pindai seluruh `process.env` untuk fallback bertanda `default|dev-|change_me` — hanya dua yang ditemukan, keduanya sudah diperbaiki.

### 9. Handoff
Selesai. Guard ditaruh sekali di `lib/security/jwt.ts` (`requireJwtSecret`, di-export) lalu dipakai ulang, sehingga tidak tersisa `process.env` untuk rahasia di `guest.service.ts`.

## BUG-002 — `dummyVerify()` tidak menyamakan waktu respons (orakel waktu)

- **Severity:** P1
- **File:** `lib/security/hash.ts:50` (sebelum perbaikan)
- **Reporter Agent:** Agent Perbaikan Bug

### 1. Expected Behavior
Saat slug QR tidak ada, respons memakan waktu setara dengan bcrypt cost 12, sehingga keberadaan QR tidak bisa dibedakan dari luar.

### 2. Actual Behavior
`dummyVerify()` membandingkan terhadap string `'$2b$12$invalidhash...'` berukuran **62 karakter**. Format bcrypt valid = 60 karakter, sehingga bcryptjs menolaknya dan selesai seketika.

### 3. Reproduction Steps
1. `bcrypt.compare('dummy-input', '<hash 62 karakter>')` → ~1 ms.
2. `bcrypt.compare('x', await bcrypt.hash('x', 12))` → ~241 ms.
3. `GET /r/<slug-tidak-ada>` vs `GET /r/<slug-ada>` → selisih respons ±240 ms.

### 4. Evidence
- Pengukuran langsung: `bad-hash ms 1` · `cost12 ms 241`.
- Test regresi: `secret-guards.test.ts` → `BUG-002: dummyVerify` (harus `> 50` ms).
- Relevant endpoint: `POST /api/guest/verify` (pemakaian `guest.service.ts:84`).

### 5. Impact
- Affected user: pemilik QR (kerahasiaan keberadaan kode).
- Security impact: **enumerasi slug** aktif, melemahkan kontrol rate-limit berbasis keberadaan QR.
- Data integrity impact: tidak ada.

### 6. Suspected Root Cause
Asumsi bahwa `bcrypt.compare` selalu memakan cost-12 waktu; ternyata hanya untuk format hash yang valid. Terverifikasi.

### 7. Reproduction Reliability
Always reproducible.

### 8. Suggested Investigation
Periksa tempat lain yang mengklaim "constant-time" — ditemukan satu (BUG-004, sudah diperbaiki).

### 9. Handoff
Hash cost 12 asli dibuat sekali dan disimpan sebagai `Promise` sehingga pemanggilan paralel pertama hanya menghitung sekali.

## BUG-004 — `loginAdmin()` bukan constant-time untuk email yang tidak ada

- **Severity:** P1
- **File:** `lib/services/auth.service.ts:77` (sebelum perbaikan)
- **Reporter Agent:** Agent Perbaikan Bug

### 1. Expected Behavior
Komentar menyatakan "Dummy compare jika admin tidak ada (constant-time)".

### 2. Actual Behavior
Nilai yang dikembalikan adalah `false` langsung — tanpa bcrypt sama sekali. Respons untuk email tak dikenal kembali dalam milidetik, sedangkan password salah pada akun nyata butuh ±240 ms.

### 3. Reproduction Steps
1. `POST /api/admin/auth/login` dengan email yang tidak terdaftar → respons cepat.
2. Ulangi dengan email terdaftar + password salah → respons lambat.
3. Selisih waktu mengonfirmasi keberadaan email.

### 4. Evidence
- Relevant file: `lib/services/auth.service.ts:71-74` setelah perbaikan (`:76-77` sebelumnya) — komentar menyatakan constant-time, implementasi mengembalikan `false` instan.
- Perbaikan memakai ulang `dummyVerify()` yang sudah diperbaiki di BUG-002.

### 5. Impact
- Security impact: enumerasi email admin dari internet tanpa autentikasi.
- Functional impact: tidak ada.

### 6. Suspected Root Cause
Salin-tempel dari pola `guest.service.ts` tanpa membawa pemanggilan dummy hash. Terverifikasi.

### 7. Reproduction Reliability
Always reproducible.

### 8. Suggested Investigation
Tidak ada lagi: grep `constant-time` di `lib/` hanya menemukan 4 tempat, semuanya sudah benar sekarang.

### 9. Handoff
Selesai.

## BUG-003 — Fallback salt pada hash IP

- **Severity:** P2
- **File:** `lib/security/hash.ts:19` (sebelum perbaikan)
- **Reporter Agent:** Agent Perbaikan Bug

### 1. Expected Behavior
`sha256(ip + salt_harian)` dengan rahasia khusus deployment, sesuai PRD §7.4.

### 2. Actual Behavior
`const salt = process.env.SCAN_SALT ?? 'default-salt'` — salt yang sama untuk semua deployment.

### 3. Reproduction Steps
1. Set `SCAN_SALT` kosong.
2. `hashIp('203.0.113.7')` tetap menghasilkan hash yang sudah dapat diprediksi.

### 4. Evidence
- Test regresi: `secret-guards.test.ts` → `BUG-003: hashIp`.

### 5. Impact
- Security impact: bila tabel `scan_events` bocor, IP asli dapat dipulihkan lewat rainbow table karena formatnya deterministik.
- Data integrity impact: tidak ada.

### 6. Suspected Root Cause
Guard yang tidak diterapkan seragam pada semua rahasia env. Terverifikasi.

### 7. Reproduction Reliability
Always reproducible.

### 8. Suggested Investigation
`.env` lokal berisi `SCAN_SALT` 36 karakter (aman); bug ini hanya aktif bila env tidak terisi di deployment.

### 9. Handoff
Selesai. Perilaku sekarang fail-closed: error, bukan merekam data dengan proteksi semu.
